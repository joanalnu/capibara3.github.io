:::tip[Summary]
Git is essentially a "Time Machine" for your code. It allows you to save snapshots of your work, experiment with new ideas without breaking your main project, and collaborate with others without overwriting their files. The goal of this is to configure the Git version control software on your device and learn basic commands.
:::

:::caution[Prerequisites]
- [Unix](../101_unix)
- [Terminal](../102_terminal)
:::


## 1. Why Git?

Git is the most widely used version control system in the world.

* **Version Control**: Easily go back to a previous version of your code if you break something.
* **Experimentation**: Use 'branches' to try out new ideas in a safe sandbox, supporting non-linear development.
* **Collaboration**: Multiple people can work on the same file simultaneaously with a clear history of changes.
* **Integration**: Seamless integration with GitHub.
* **Standards**: Almost every professional software team uses Git.


## 2. Setup and Configuration

First, you must download Git from the official website.

1. Download Git from [git-scm.com](https://www.google.com/search?q=https://git-scm.com/downloads).
2. Follow the installation instructions for your specific operating system.
3. Verify the installation by running `git --version` in your terminal.

Before you start saving work, Git needs to know who is making the changes. Set up your name and email using your planned GitHub credentials.

```bash
git config --global user.name "Your Name"
git config --globeal user.email "your.email@example.com"
```

You can check your configuration by running `git config --list`.


## 3. The Basic Workflow

The most important concept in Git is the **Three-Stage Workflow**. You move files through these steps rather than just saving them:

1. **Working Directory**: Where you are currently typing the code.
2. **Staging Area**: Using `git add <filename>` marks files that are ready to be saved.
3. **Local Repository**: Using `git commit -m "Commit Message"` permanently saves those marked files with an explanatory message.

:::tip[Unix Folder System]
As discovered in the terminal guide, `../` describes the path to the parent folder, while `.` describes the current folder. Running `git add .` adds every files and folder in your current working directory to the staging area.
:::

## 4. Git Commands Reference

### Basic Commands

* `git init`: Initializes a new Git repository in the current directory.
* `git clone [url]`: Clones a repository from a given URL.
* `git status`: Displays the status of the repository, including staged and unstaged changes.
* `git add [path]`: Stages a specific path for the next commit.
* `git add .`: Stages all changes in the current directory and subdirectories.
* `git commit -m [message]`: Commits staged changes with a meaningful description.
* `git log`: Displays the history log of all commits made to the repository.

### Branching and Merging

Creating a **Branch** allows you to try new ideas without ruining your working code.

* `git branch [branch-name]`: Creates a new branch.
* `git checkout [branch-name]`: Switches you over to a different branch.
* `git merge [branch-name]`: Merges changes from another branch into your current main code.
* `git branch -d [branch-name]`: Deletes a branch.

:::note[Example: Cosmic Ray Simulator]
Imagine you have a Python package defining a cosmic ray physical model, and you want to implement a more accurate version without ruining the working code. You create a branch where you can rewrite the model safely. If it succeeds, you merge the branch with the main one; if it fails, you delete the branch and forget about it.
:::


### Remote Repositories

* `git remote add [name] [url]`: Adds a remote repository.
* `git fetch [remote-name]`: Fetches changes from a remote repository.
* `git push [remote-name] [branch-name]`: Pushes your local changes to a remote repository.
* `git pull [remote-name] [branch-name]`: Pulls changes from a remote repository and merges them into the current branch.

### Undoing Changes

* `git reset [file]`: Unstages a file.
* `git reset --hard`: Discards all changes and resets the repository to the last commit.
* `git revert [commit-hash]`: Reverts a specific previous commit.

### Other Commads

* `git diff`: Displays the differences between the current version and the last commit.
* `git tag [tag-name]`: Creates a new tag.
* `git --all`: Displays a graphical representation of the commit history.
